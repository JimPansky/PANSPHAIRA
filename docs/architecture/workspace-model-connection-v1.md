## Existing owners and default-off mount

The optional `modelConnections` attachment on `enableWorkspaceBrowserV1` reuses the existing protected origin/session authority, existing personal-profile SQLite database, owner-private file read primitive, `ModelAccessBrokerV1`, and atomic resource-budget SQLite ledger. It creates no credentialstore or general controller. Absence of the optional attachment retains the original browser. An explicitly attached empty list renders no authorized product route; inference remains NOT_RUN.

The separate browser module does not enlarge the original shell app bundle or relax the existing 131072-byte per-asset boundary. It offers server-owned connection IDs only: no free URL, secret/password, arbitrary provider or assumed OAuth/device flow. Selection writes only reference/identity/check/consent metadata to the same existing profile database. A mutation response is followed by a separate native GET. Full reference, model and evidence class are wrapped outside the native select for both the uncommitted browser choice and the separately confirmed persisted reference. A draft differing from that native reference disables consent and probes; selection itself performs no mutation or grant. During a pending independent GET, a preceding POST acknowledgement does not become a final persistence assertion. Lost mutation replies are never replayed; only a new independent read is offered.

Availability and readiness are invalidated by changed identity, secret, expiry or revoked session. The genuine 60-second check lifetime remains unchanged.

A code-owner attachment pins exact adapter/parser file bytes, model/deployment, configuration revision, HTTPS public IPv4 target set, or explicitly local 127.0.0.1 target. The raw response is never returned to the browser. Parser/model/usage/format/secret-echo failures do not produce an acceptance claim. Existing strict canonical JSON is unchanged; the generic chat adapter now omits absent optional response_format instead of inserting undefined.

## Consent, price, budgets and unknown usage

No product grant is the default. A concrete owner grant is separate from explicit exact once-only browser confirmation and bound to route identity, public test-data digest, expiry and maxima. Browser consent also binds the authenticated session ID and a digest of the complete current owner grant, including every limit; a replacement login keeps the reference but inherits no consent. Owner-grant changes invalidate consent without changing route/ledger identity or resetting aggregate usage. Every asynchronous dispatch admission rechecks all grant limits and prerequisite expiry. Native remaining capacity determines the offer/readiness and is checked again before consent and dispatch. Pending DNS admission and actual HTTP requests are bounded by the existing deadline and aborted on native owner retirement; late DNS results cannot open a socket. The visible closed offer discloses all eight limits, test-data digest, pricing class, currency and price revision. Code-owned synthetic zero price is explicitly not product consent. A worker subscription, credential availability or HTTP200 cannot create that grant. The probe sends only fixed public synthetic qualification text, no customer content or UI tool actions. Price/currency/revision must be bound for non-synthetic calls. Conservative BigInt input/output price ceilings reject an unaffordable request before network dispatch.

The existing native ledger reserves the maximum cost and request slot before dispatch. UNKNOWN_USAGE retains the full reservation across reopen and route changes; selection or a new consent cannot erase it or trigger a blind retry. No arbitrary client amount, evidence digest or HTTP completion can settle a real unknown bill. A qualified independent provider-usage reader is not present for an actual product route; real unknown usage stays held. The owner-local synthetic-only reconciliation derives zero from its code-owned nonbillable class and marks FAILED/no model PASS, never fabricates a real usage response. It is not an HTTP endpoint.
