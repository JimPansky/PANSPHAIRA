## Crash, timeout, explicit abort and recovery

The workload deadline is fixed at 15000 ms and output is bounded. `controller.activeEvidence()` lets the existing trusted owner observe actual native progress, and `controller.abort()` stops only that owner's active workload. Crash, timeout or explicit abort after a native effect produces `OUTCOME_UNKNOWN` and `REQUIRES_NATIVE_RECONCILIATION`. No automatic effect retry occurs. Further runs return `UNRECONCILED_NATIVE_EFFECT` until `controller.reconcile(report)` rereads the actual native session and its verified compensation receipt. Normal `controller.close()` also refuses unresolved native effects with `PAN576_NATIVE_RECONCILIATION_REQUIRED`; shutdown cannot silently erase the owner-local fence or target evidence. A failed/unknown workflow does not become a successful composition merely because its synthetic effect was compensated.

Cleanup is bound to the actual created ID and its exact invocation label. Other-invocation containers remain unchanged. A lost cleanup-control response cannot silently clear authority: the owner retains `pendingOutcome()`, blocks new runs with `OWN_RESOURCE_OR_EFFECT_RECONCILIATION_REQUIRED`, and refuses normal close. `controller.recoverPending()` rereads exact owned resource identity/absence, removes only that known resource/staging and verifies the retained native target/receipt before clearing the fence. Its response explicitly retains `automaticRetryPermitted:false`.

All grants, reports, signing material, unknown-effect fences and native target sessions are owner-process memory. This is not crash-durable Exactly-once, persisted restart/recovery, real-provider rollback or reverse of production effects. #578's stored-artifact/context-restart journey remains separate.
