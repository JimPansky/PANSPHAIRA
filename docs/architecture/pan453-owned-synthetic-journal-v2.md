# PAN453 owned synthetic journal v2 — bounded source slice

`createLocalBusinessOperation` retains its published legacy behavior on legacy roots. It refuses the reserved `pan453-owned-v2` directory. The new `createOwnedSyntheticBusinessOperation` requires that directory component and only accepts the fixed synthetic Order binding from PAN442. The new adapter never adopts journals from a legacy root. On this version's direct gate/workbench entry points, the reserved directory refuses construction even before its mode file exists. Thus the old direct writer cannot pre-open that namespace and race the initial mode write; the earlier v1 mode-in-place candidate was rejected after a deterministic check/write interleaving. A legacy direct root remains legacy and cannot be migrated by this adapter.

Only the v2 namespace may bypass pre-effect snapshot drift for a durable, lease-matched AMBIGUOUS reservation with read-only reconciliation; legacy direct gates retain their stale-snapshot denial. File-flush and directory-sync barriers for the two journals are likewise scoped to v2; legacy persistence semantics remain unchanged.

The owned adapter writes a versioned mode marker and holds a local exclusive owner marker through both journal readers, approval, effect and provider callback. A competing process and direct constructors on that owned root refuse before a write. The token is module-private, but the exported local owner acquisition is not a security authorization boundary: callers with same-user filesystem/code execution remain outside this contract. A crash retains the marker and the adapter refuses automatic resume. Removal/replacement of stale markers, recovery after killed owners, bounded stop/revoke during recovery, consistent multi-file snapshots, and actual external target authority are not implemented here. A separate fresh root restored with mode and *both* journal bytes exercises only synthetic read-only reconciliation; missing authority refuses. Do not remove a retained owner marker to force a retry.

Environment: local Node 24, single host/single filesystem, isolated process fixtures and synthetic in-memory/file target only. No OS sandbox, multi-host lock, filesystem-adversary protection, power-loss durability, installation/runtime activation or productive effect is claimed. No coexistence with processes using older code versions is supported on the same v2 namespace. The provider's independent synthetic `reconcile` read is not an authoritative business-system target read. PAN453 acceptance remains open for external target/stop/revoke and independent runtime qualification. PAN454 host crossing conformance remains separate.
