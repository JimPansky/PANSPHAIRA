# Personal native module views and the connected ERV Human browser

## Bounded implemented contract

This opt-in extension composes the existing protected browser shell, native
context/selection owner, personal profile store and PAN542 Human ledger. It is
not a second shell, document service, approval engine or production interface.
The initial supported domain is the existing code-owned LOCAL_SYNTHETIC ERV
invoice pair. Authenticated native membership determines visibility and reads;
DOM, layout, source digests, model proposals and JSON role fields never grant
permission. The shared personal layout profile v1 remains its own unchanged
state. Module views are additive, versioned and data-free.

A working tree, API PASS, source archive or screenshot alone is NOT_DELIVERED.
Original issue546 completion additionally requires its entire connected browser
journey, focused independent review, affected visual qualification, exact
required CI/WholeCanonical, protected merge, functional release and anonymous
artifact readback. This contract does not complete original548 or the separate
KS consumer build.

## Native facts and mandatory rendering

`pansphaira.workspace-data-catalog/v1` advertises only actual allowed fields
from the existing native ERV reader and independent Human read. Reads are
limited to two native objects, eight fields, one row and no free queries or
arbitrary relation traversal. Values carry source, real source revision, unit
and leading store. Missing supplier/assignee/document-number projections are
explicitly UNAVAILABLE, not inferred facts.

The closed `pansphaira.workspace-erv-references/v1` projection shows the actual
invoice, native order, native position and native receipt IDs, confirmed
quantity unit and admitted invoice source path/SHA256. It reconstructs the
existing native purchase snapshot and compares native revision, binding digest
and liability basis with the authenticated Human read before returning data.
It does not multiply invoice rows by receipts or create a general DMS/search
service. The browser runtime validates the exact reference shape and bounds.

The existing read-only invoice surface and opt-in Human surface remain outside
personal view hiding/rebinding. Amount and native Human-state view elements are
mandatory; layout writes cannot remove effective native authority boundaries.
Personal view metadata contains no invoice values, tenant credentials or grants.

## Preview, confirmation, persistence and Undo

`pansphaira.workspace-module-view/v1` and its closed delta use the same validator
and reducer for manual and AGENT callers. AGENT is a proposal channel, not
proof of a real text model. Supported operations are MOVE, RESIZE, SHOW and
BIND within the native catalog. Wrong units, fields or protected mutations deny.

A native preview is bound to the authenticated context, selection/source/view
revisions, expected CAS revision, exact before/after digests and finite lease.
Preview/cancel produce no personal persistence or business effect. The browser
requires explicit confirmation of that candidate. A dispatched candidate is
marked attempted before awaiting, including the handler and disabled UI state.
An unknown write result cannot offer that same candidate as a blind retry.
Native single consumption, post-reservation authentication and CAS remain in
force. Save success requires an independent native GET matching the new CAS,
view digest and confirmed candidate digest, never a receipt alone.

Personal views/history use separate SQLite tables in the existing profile
store; historical browser profile v1 bytes and native business journals remain
separate. Logout/login and a fresh process can read the persisted view. Saved
Undo is another preview, explicit consent and a new current CAS revision; it
cannot overwrite concurrent changes or rewind history.

## Connected native Human journey

The browser can open a real in-app native notification before first ERV visit,
load its exact current invoice and show a concrete Human state/revision diff
before explicit decision. REVIEW, QUERY and separately authorized
APPROVE_LOCAL_EVIDENCE_ONLY call the existing PAN542 contract. Reader controls
stay disabled. Native role, session, origin, tenant/object/context lease,
proposal revision/digest, task fence and duplicate/effect rules remain native.
The final native authorization/principal/owner guard is checked after the real
SQLite writer reservation, not just before waiting.

Human approval is local evidence only: no booking, payment or productive
execution authority. An independent native read must match the persisted event
and proposal after a decision; current personal view source cells then refresh.
A genuine lost decision reply remains UNKNOWN until read-only reconciliation;
there is no automatic decision retry. Stale proposal, forged scope/role and
missing Human attachment do not turn a separate API success into browser success.
Notification permission denial is isolated only for the explicit native-role
code while the session is still valid; unknown denials remain fail-closed.

The same positive browser run changes the contextual right-hand panel/profile,
logs out/in and verifies restored layout plus unchanged native decision history.

## Build, lifecycle and reproducible qualification

The existing locked compiler builds the main workspace and a separately served,
owner-opt-in Human ESM asset with the same pinned minification policy. The
original 131072-byte per-script ingress bound is unchanged for each. A sum of
separate assets is not a single-bundle or KS composition acceptance. Loading the
Human asset is nonblocking and abort-bound; failure must leave other navigation
and logout usable. No new dependency, global harness, provider or protection rule
is introduced.

Run `npm run pan546:test` in the existing supported Linux x86-64 Node24 tooling
with owned scratch, actual Chromium and certificate tooling. The fixed entry
runs every registered native/shared-contract/TLS/reservation/browser/registration
case without caller selection. A trusted Node/npm parent remains required.
The canonical `npm test` pretest consumes this entry without replacing older
entries. Missing tooling fails rather than skipping.

Browser evidence records exact built asset/source hashes, synthetic native
invoice/Human revisions, state, actual requests/responses and viewport. The
positive connected journey plus directly affected denied/stale/duplicate/unknown
cases includes real Desktop/390-px screenshots, dimensions, focus and 200% CSS
zoom. Full product PNGs are visually compared with the appropriate Notebook and
Prism references; concept images are not product pixels, authority or a mandatory
five-design/four-profile matrix. Unchanged qualified evidence may be reused only
with exact byte/provenance binding.

No real text-model tool loop, voice/router/training, external inference/data
access, productive customer workflow, universal compatibility or Human study is
claimed. The early delivered548 context slice is not republished by this work.
